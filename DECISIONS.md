| 15 | Branch operand semantics | `imm32` = **offset relatif ke instruksi branch itu sendiri**, dalam satuan instruksi, dihitung pada koordinat pc seluruh VM_CODE section (fungsi dikonkatenasi, sama seperti pc VM). Label assembler = pc absolut, lalu dikonversi `target - index`. | Agent | 2026-11-07 |
| 16 | Throw = completion | `dispatch` mengubah `VmThrow` apa pun (operator, capability bridge, opcode tak terdukung) menjadi `Signal.Throw` + `frame.suspension`; ia tidak pernah membiarkannya keluar dari `step`. Penugasan pc ke exception mengpakai `frame.enteredAt` (instruksi yang sedang berjalan), bukan `pc` yang sudah maju. | Tanpa konversi ini `try { 1n + 1 } catch (e) {}` melempar ke host dan handler tidak pernah jalan; tanpa `enteredAt` range setengah-terbuka yang berakhir di instruksi pelempar akan dilewati. | Agent | 2026-11-07 |
| 17 | Exception table = function-local (v2) | Setiap record menyimpan `fnIndex`; record `startPc`/`endPc`/`handlerPc` **relatif ke badan fungsinya**, dan `groupRecordsByFunction(records, functionCount)` mengelompokkannya ke `functionExceptions[fnId]` berisi record dengan pc fungsional (bukan section-absolute). `unwind()` membaca `program.exceptions[frame.functionId]` dan membandingkan dengan `frame.enteredAt` apa adanya. Tabel v1 (section-absolute) ditolak saat decode dengan hint recompile. Setiap fungsi mendapat grup, termasuk yang kosong. | Tabel flat section-absolute harus memilih pemenang di antara rentang yang tumpang tindih dan bisa merutekan throw `fn0` ke handler `fn1` yang frame-nya belum pernah dimasuki. Kunci per-fungsi membuat kecocokan offset antar-fungsi tak berbahaya secara konstruksi. Grup kosong membuat `unwind` total tanpa cabang khusus. | Agent | 2026-11-07 |

| 18 | Slice pertama Phase 3 | Emitter hanya menerima satu fungsi tanpa parameter dengan body `return <aritmetika>`; operator `- * / % **`, literal numerik, unary `-`/`+`. `+` **ditolak** (`KXOBH-E-COMPILER-UNSUPPORTED`), begitu juga identifier, statement, parameter. Setiap node di luar slice gagal build dengan file:line:col + feature + action. | `+` adalah konkatenasi string bila salah satu operand string, jadi menuliskannya sebagai `ADD` akan menghasilkan program yang lolos verifier tapi salah nilai. Yang sama berlaku untuk identifier (butuh scope prologue). Menolak dengan posisi nyata lebih jujur daripada mengcompile sebagian. | Agent | 2026-11-07 |
| 19 | Batas numerik literal | Literal integer dalam rentang int32 dan bukan `-0` → `LOAD_NUMBER imm32`; selain itu ke constant pool lewat `LOAD_CONST` (termasuk `1e300`, pecahan, `2147483648`). Negatif bukan literal: `-5` diturunkan sebagai `LOAD_NUMBER 5` + `NEGATE`. Pool diintern per-nilai dengan `Object.is` sehingga `0` dan `-0` terpisah. | `imm32` hanya 32-bit dan `-0` tak bisa diperdebatkan lewat integer; melewati pool membuat nilai bit-exact. Menurunkan negatif sebagai NEGATE membuat ambang `-2147483648` tidak perlu kasus khusus. | Agent | 2026-11-07 |
| 20 | Register sebagai accumulator tunggal | Operand kanan dilepas (`regs.release(mark)`) tepat setelah instruksi biner, sehingga `2*3*4*5` memakai 2 register, bukan 5. Jika register habis → `KXOBH-E-COMPILER-UNSUPPORTED` berposisi, **bukan** index slot atau register fiktif. Spilling belum diemit (`LOAD_LOCAL`/`STORE_LOCAL` belum ada). | Memberi kembali nomor register yang tidak pernah diberikan allocator akan menimpa temporary yang masih hidup — bug aliasing yang dilarang Spec §9.1. Pelepasan dini aman karena instruksi biner mengonsumsi operand kanan sekali dan pemanggil tak bisa mengamatinya. | Agent | 2026-11-07 |
| 21 | Pool per-fungsi direbase saat build | `emitFunction` mengembalikan `constants` sendiri dengan indeks lokal; `buildSections` menggeser `imm32` setiap `LOAD_CONST` sebesar panjang pool sebelumnya. | Tanpa rebase, fungsi kedua yang memakai konstanta #0 akan membaca literal milik fungsi pertama — program tetap lolos verifier karena indeksnya valid, jadi kesalahan ini tidak akan tertangkap verifier. | Agent | 2026-11-07 |
| 22 | `+` dilower hanya bila terbukti Number | `provesNumber` membuktikan operand lalu `+` → `ADD`. Bukti: literal number/`null`, unary `+`/`-` atas operand terbukti, dan binary `+ - * / % **` atas dua operand terbukti (rekursif, jadi `(1 + 2) + 3` terbukti). Selain itu `KXOBH-E-COMPILER-UNSUPPORTED` dengan feature `binary + where an operand is not provably a Number`. | `+` adalah AdditiveExpression: konkatenasi bila ada operand String/objek ber-hook, jadi `ADD` yang ditulis tanpa bukti lolos verifier tapi salah nilai. Bukti satu arah: boleh menolak `+` yang sebenarnya Number (over-rejection), tidak boleh menerima selain Number. Bukti **harus** menembus `+`, kalau tidak bukti berhenti satu level dan `(1 + 2) + 3` ditolak tanpa alasan. Kurung tidak penting karena parser membuang `Paren` — bukti dan emitter melihat struktur yang sama. | Agent | 2026-11-07 |
| 23 | `null` dilower sebagai `+0` | Literal `null` → `LOAD_NUMBER 0`. | `ToNumber(null)` = `+0` dan `null` satu-satunya literal non-number tanpa hook `+` sendiri; menolaknya membuat program valid gagal build tanpa alasan semantik. String/boolean/bigint/regexp tetap ditolak karena tipenya sendiri. | Agent | 2026-11-07 |
| 24 | Deklarasi sebelum `return` dieksekusi, isinya tak bisa dibaca | `const`/`let`/`var` dengan initialiser diemit (urutan evaluasi sama dengan native); register hasil initialiser dilaporkan di `EmittedFunction.bindings`. Membaca binding tetap ditolak (`reading binding "x"`). | Initialiser punya efek (lempar, hitung) yang terlihat; membuangnya sebagai "dead" mengubah perilaku. Membaca butuh scope prologue (`LOAD_LOCAL`) yang belum ada, dan menurunkan read sebagai "register yang kebetulan sama" akan alias. `bindings[].register` harus `< registerCount` agar prologue nanti tidak membaca di luar frame. | Agent | 2026-11-07 |
| 25 | Budget register di-clamp ke `maxRegisters` VM | `resolveEmitLimits` menurunkan `registerCount` ke `vmLimits.maxRegisters`; `compileSource` meneruskan `vmLimits` yang sama ke `assembleProgram`. | Budget lebih lebar dari batas VM hanya bisa berujung verifier error yang terbaca seperti bug compiler. Clamp rendah aman: lebih cepat menolak ekspresi lebar (diagnostic berposisi), tidak pernah menghasilkan kode salah. | Agent | 2026-11-07 |
| 26 | Binding hidup di frame **slot**, bukan register | Tiap deklarasi mendapat slot dense dari 0 (`slot = 0..localCount-1`), bernomor urut deklarasi. `frame.slots` adalah array terpisah dari `frame.registers`, jadi dua ruang itu **tidak bisa alias**; verifier memeriksa tiap `LOAD_LOCAL`/`STORE_LOCAL` terhadap `paramCount + localCount`. Membaca binding = `LOAD_LOCAL slot`; assignment/compound/prefix update = `STORE_LOCAL slot`. `EmittedFunction.bindings` melaporkan `name`/`kind`/`slot`. Spilling tetap ditolak: allocator memberi nomor spill dari `registerCount`, array slot frame tidak sampai ke sana, dan penjangkauannya butuh `LOAD_LOCAL`/`STORE_LOCAL` yang disediakan untuk binding. | `registerCount` adalah milik allocator untuk temporary ekspresi; `frame.slots` array terpisah berarti memakai ulang nomor bisa (dan akan) saling timpa tanpa verifier sadar. Subsumes DECISIONS #24: `bindings[].slot` menggantikan `bindings[].register`, dan "initialiser dieksekusi" tetap benar — nilai kini *disimpan* ke slot, sehingga binding bisa dibaca ulang. | Agent | 2026-11-07 |
| 27 | TDZ & konstanta dilanggar = build error, bukan runtime | `let`/`const` dipublish ke peta scope saat deklarasi, tetapi `state`-nya `declared` sampai initialiser miliknya sendiri selesai (dua pass: alokasi+diterbitkan dulu, initialiser kedua). `let a = b, b = 1` ditolak (b masih `declared` saat dibaca); `let a = 1, b = a` lolos. `var` langsung `initialized` (hoisting). Baca `declared` → `reading <kind> binding "x" before its declaration has run`; tulis `const` → `assignment to const binding "x"`; redeklarasi nama yang sama → `redeclaring binding ...`. Postfix `x++` yang nilai lamanya dipakai ditolak (harus menjaga nilai lama). | Native melempar `ReferenceError` (TDZ) / `TypeError` (const) di runtime; compiler belum emit exception handling, jadi menurunkan program itu akan mengembalikan nilai di mana native melempar — perbedaan perilaku yang wajib ditolak saat build, posisinya nyata. | Agent | 2026-11-07 |

## Asumsi arsitektural

- Bytecode pakai **nilai JS native** di register, bukan representasi kustom (Spec §8.3).
- Closure mutable binding di-box lewat shared environment cells (Spec §9.5).
- Async = state machine resumable, tidak blocking event loop (Spec §9.6).
- Verification penuh sebelum eksekusi; GCM authenticate sebelum decompress (Spec §13.4).
- `inspect` hanya metadata aman; `verify` non-eksekusi (Spec §3.3).
